# 5단계 — LLM Provider 연결과 실제 AI 기능 출시

> 상태: 부분 구현(남은 항목 있음; 05-implementation-status.md 참고) · GitHub 이슈: AI-13 ~ AI-20 + 기업/직무/지원 전략 확장 · 선행: [4단계](./04-coverletter-interview-contracts.md) · 외부 토큰: 필요
>
> **주의:** 5단계는 개발량이 크다. 단일 PR/릴리스로 합치지 말고 5A~5E의 작은 수직 기능 단위로 끊어 출시한다. 1~4단계의 토큰 없는 API와 데이터는 그대로 재사용한다.

## 목표
Mock 기반 계약을 실제 LLM 호출로 교체하고, 경험 대화·요약, JD/기업/직무 분석, 경험 매칭/지원 전략, 자소서 생성·첨삭, 면접을 **각각 독립적으로 테스트·배포**한다.

## 5A. 실제 Provider와 운영 안전망 — AI-13
- [ ] `AiProvider` 포트 뒤에 `SpringAiProviderAdapter`를 구현한다. **우선 1개 Provider만** 연결하고 다른 업체 추가는 실제 필요가 생긴 뒤.
- [ ] Spring AI의 공식 모델 starter/`ChatModel`을 어댑터 안에서 사용한다. 비즈니스/DTO에 업체 SDK 타입을 노출하지 않는다.
- [ ] `AI_ENABLED=false` 기본값, `AI_PROVIDER`, `AI_MODEL`, API Key 환경변수, 요청 시간 초과, 최대 입력·출력 토큰, 재시도·요청 횟수 제한을 정의한다.
- [ ] Secret은 환경변수/시크릿 매니저에서만 읽고 `.env.example`에는 이름만 기록한다. 실제 키·원문 대화·PDF/이력서 전문을 로그에 남기지 않는다.
- [ ] LLM 출력은 `OutputSchema` 유효성 검사 후 도메인 DTO로 변환한다. JSON 파싱 실패/빈 응답/타임아웃/429/5xx에 대해 표준 오류를 반환하고, **모델 실패 시 Mock 답변을 실제 AI 결과처럼 반환하지 않는다**.
- [ ] 사용량(토큰/지연/실패 횟수), 프롬프트 버전, 모델, 요청 ID만 관측한다. 비용 알림·사용자별 요청 제한을 둔다.
- [ ] 외부 API 키 없이 기존 `verify`가 항상 통과하도록 실제 모델 호출은 명시적 opt-in 통합 테스트로 분리.

## 5B. 경험 대화·요약·가져오기 — AI-14, AI-15
- [ ] `AI-14`: 사용자 경험 태그 + completeness 결과 + 이전 질문·답변을 기반으로 다음 **한 개의 질문** 생성. 정적 질문은 fallback으로 사용 가능하되 출처를 표시.
- [ ] 대화 세션(`experienceId`, `memberId`, 메시지 역할·순서·시간, 사용한 프롬프트 버전), 이어쓰기/중단/재개 API 설계.
- [ ] 제안 API: `POST /api/experiences/{id}/ai-chat/messages`, `GET /api/experiences/{id}/ai-chat/messages` (인증/소유권 검증).
- [ ] `AI-15`: 대화/기존 답변 → `ExperienceSummary` 구조화 생성. 원문 근거 없는 결과나 정량 성과는 생성 금지; 불충분한 필드는 `null`/보완 질문으로 반환.
- [ ] 제안 API: `POST /api/experiences/{id}/ai-summary:generate` 또는 REST 관례에 맞는 하위 경로. 생성 결과는 **preview**로 반환, 사용자가 확인한 뒤 2단계 저장 API로 확정.
- [ ] PDF/공개 Notion·URL 텍스트에서 경험 후보 추출 시 `sourceId`와 원문 위치를 포함. 사용자 확인 없는 타인 자료 자동 저장 금지.

## 5C. JD·기업·직무 분석과 지원 전략 — AI-16 + 확장
- [ ] `AI-16`: 저장된 `JobPosting.jdOriginal` 또는 사용자가 제공한 공고 텍스트 → `JobAnalysis`, `RoleAnalysis` 추출. JD의 요구/우대/업무를 분리하고 근거 원문을 연결.
- [ ] 기업 분석: **검증 가능한 출처**가 제공되거나 허용된 공식 자료를 수집한 경우만 `CompanyAnalysis` 생성; 최신 여부/출처/수집 시각 표기. 자료가 없으면 "분석 불가" 명시.
- [ ] 직무 분석: JD 기반 필요 기술·역량, 주요 업무를 설명하되 공고에 없는 사실은 추측으로 구분.
- [ ] 기존 `GET/PUT/DELETE /api/cover-letters/{coverId}/posting`을 보존하고 `POST /api/cover-letters/{coverId}/posting/analyze`로 명시적 분석 트리거 분리.
- [ ] 지원 전략: JD 요구 역량 + 사용자 경험·규칙 매칭 → 추천 경험 및 강점/부족한 증거/보완 전략. 예측 합격률·허위 수치 사용 금지.
- [ ] 임베딩/시맨틱 매칭은 품질·비용 근거가 생길 때 v2로 실험; 3단계 규칙 점수를 갑자기 의미적 점수처럼 재정의하지 않는다.

## 5D. 자소서 문항 분석·초안·첨삭·채팅 — AI-17, AI-18, AI-19
- [ ] `AI-17`: 문항 텍스트 → `QuestionType`, 평가 의도, 권장 역량, 근거/불확실성 구조화. 3단계 매핑의 수동 유형 선택도 그대로 지원.
- [ ] `AI-18`: 4단계 `CoverLetterContextBuilder`와 선택 경험/JD로 초안 생성. 사용자가 사실을 제공하지 않은 프로젝트·성과·직무 경험은 꾸며내지 않음.
- [ ] 제안 API: `POST /api/cover-letters/{coverId}/questions/{questionId}/draft`. 초안 결과에 `text`, `characterCount`, `warnings`, `usedExperienceIds`, `provider`/`promptVersion` 포함.
- [ ] 서버에서 글자수(유니코드 코드포인트) 확인. 초과하면 후처리 재요청 또는 안내; 강제 자르기로 의미를 훼손하지 않는다.
- [ ] `AI-19`: `RevisionType`(GENERAL/LOGIC/CONCISE/JOB_FIT/GRAMMAR/IMPACT) 별 첨삭, 변경 이유·기존/새 텍스트 비교 반환.
- [ ] 문항별 AI 채팅을 위한 세션/메시지 API 추가. 대화 맥락은 해당 사용자의 문항·경험만 포함하고, 삭제된 경험 링크를 무단 재사용하지 않는다.
- [ ] **초안·첨삭 결과는 별도의 미적용 상태**로 보관하고 사용자가 적용할 때 기존 답변 저장/버전 API를 호출한다. 응답 수신 즉시 `answerText` 덮어쓰기 금지.

## 5E. 면접 Beta — AI-20
- [ ] 자소서·이력서·직무·기업·행동·꼬리질문 유형별 질문 생성. 원문 사용 사실을 질문 메타데이터로 기록.
- [ ] 사용자 답변을 받은 뒤 STAR·직무 적합성·구체성에 대한 설명형 피드백, 근거 있는 꼬리질문 1개 생성.
- [ ] `InterviewContext` 기반 면접 세션 상태, 턴 순서, 중단/재개, 이력 조회 API(예: `/api/interviews/sessions`)를 설계·구현한다.
- [ ] 최초 Beta는 텍스트 턴 기반. 실시간 음성·영상, 스트리밍·감정 분석·합격 가능성 예측은 범위 밖.
- [ ] 프롬프트 실패·사용자 중단 시 마지막 저장된 세션을 보존하고 중복 요청으로 같은 턴이 두 번 생성되지 않도록 한다.

## 공통 안전/품질 설계
- LLM에게 보내는 사용자 입력, URL 본문, PDF 텍스트를 **시스템 지시로 취급하지 않는다**. prompt injection·개인정보 유출·무단 외부 요청 방어.
- 권한/소유권 검증은 모델 호출 **전** 수행하고, 다른 회원의 경험·문항·파일은 Context에 섞지 않는다.
- 원문 출처/증거를 확인할 수 없는 기업 사실·수치·성과는 **미확인**으로 표시. 분석 실패 시 사용자가 원문을 수동 입력할 수 있게 한다.
- 사용자 동의에 따른 AI 호출/원문 전송 범위·기록 보존/삭제 정책을 수립한다. 개발·테스트용 프롬프트와 운영 데이터는 분리한다.
- 테스트는 Mock·고정 fixture 우선; AI 출력 품질은 한국어 예제 세트에서 사실성, 스키마 유효성, 글자수, 질문 중복, 근거 연결을 별도 평가한다.
- 비용: 요청별 토큰 상한·리트라이 제한, 사용량 및 예산 임계값 추적; 호출 실패가 기존 수동 작성 API 장애로 전파되지 않게 한다.

| 소단계 | 운영에 공개할 기능 | 검증 기준 |
| --- | --- | --- |
| 5A | Provider 통신(개발/내부) | 키 미설정 시 안전하게 비활성, 오류 매핑·계약 테스트 |
| 5B | 경험 대화/구조화 요약 | 턴 영속화, 요약 누락·원문 근거·사용자 승인 |

## 최종 완료 기준 (DoD)
- [ ] AI-01~AI-20의 상응 기능이 구현/테스트되거나 명시적으로 베타 제외 처리되었음을 이슈에서 추적.
- [ ] 모든 실제 AI 엔드포인트: JWT 소유권, 입력 검증, 429/타임아웃 오류, rate limit, 출력 스키마 검사.
- [ ] 사용자 수정 결과가 원본/버전과 구분돼 추적 가능하고 기존 수동 기능은 독립 실행 가능.
- [ ] `be/.\mvnw.cmd verify`는 API Key 없이 통과; 실제 LLM E2E는 선택적으로만 실행.
- [ ] 장애·비용 초과 때 AI 기능만 안전하게 닫히고 경험/자소서 CRUD는 계속 사용 가능.
